# Bamboo Forest Board

타운홀 같은 팀 행사 전에 칭찬·건의·질문·하고 싶은 말을 익명 포스트잇으로 모으고, 행사 당일에는 타운홀 모드로 하나씩 꺼내 함께 이야기하는 React + TypeScript + Vite 프로젝트입니다.

## 주요 기능

- **익명 포스트잇 작성** — 카테고리별 안내 문구, 색상·사진 첨부, 작성 중 초안 자동 보관(탭이 열려 있는 동안), `⌘/Ctrl + Enter` 등록
- **비밀번호 선택 사항** — 비워두면 이 기기 전용 비밀값이 자동으로 만들어져 같은 기기에서는 비밀번호 없이 수정·삭제할 수 있습니다. 다른 기기에서도 고치려면 비밀번호를 정하면 됩니다.
- **읽기 우선 상세 화면** — 포스트잇을 누르면 전체 내용·사진·공감·댓글이 먼저 보이고, 수정·삭제는 보조 동작으로 분리했습니다.
- **보드 / 목록 보기** — 보드는 자유 배치(드래그), 목록은 겹치지 않게 정리된 카드. 목록은 기본 순서·공감순·최신순·댓글순 정렬을 지원합니다. 모바일은 목록이 기본입니다.
- **공용 순서 정리** — 상단 고정, 맨 위로/한 칸 위로/한 칸 아래로/맨 아래로 (데스크톱 우클릭, 모바일 `⋯` 버튼)
- **카테고리 탭·검색** — 내용·닉네임·댓글 검색, 키워드 통계를 누르면 해당 키워드로 바로 검색
- **타운홀 모드** — 전체 화면 발표 뷰. 공감순·카테고리순·무작위 순서, 🎲 랜덤 뽑기, "이야기 나눔" 도장(진행 기록은 발표하는 기기에 저장), 시작/마무리 슬라이드, 댓글 패널
- **NEW 표시** — 마지막 방문 이후 올라온 포스트잇
- **회차 아카이브** — 지난 회차는 읽기 전용으로 보존되고 상세·댓글·타운홀 모드 다시보기가 가능합니다.

### 키보드 단축키

| 화면 | 키 | 동작 |
|------|----|------|
| 보드 | `N` | 포스트잇 붙이기 |
| 보드 | `/` | 검색창으로 이동 |
| 보드 | `T` | 타운홀 모드 |
| 타운홀 | `→` `Space` / `←` | 다음 / 이전 |
| 타운홀 | `R` | 랜덤 뽑기 |
| 타운홀 | `D` | 이야기 나눔 표시 |
| 타운홀 | `C` | 댓글 패널 켜기/끄기 |
| 타운홀 | `F` | 전체 화면 |
| 공통 | `Esc` | 닫기 |

한글 입력 상태에서도 동작하도록 물리 키 기준으로 처리합니다.

## 회차(시즌) 관리

| 경로 | 설명 |
|------|------|
| `/board` | 현재 회차(v5) — "5기 채용혁신개발팀 대나무숲", 2026-11-09 00:00(KST) 이후 데이터 |
| `/board/v4` | 4기 아카이브 — "뉴 채용혁신개발팀", 읽기 전용, 2026-10-15 13:00 ~ 2026-11-09 00:00(KST) |
| `/board/v3` | 3기 아카이브 — 읽기 전용, 2026-06-23 ~ 2026-10-15 13:00(KST) |
| `/board/v2` | 2기 아카이브 — 읽기 전용, 2026-05-04 ~ 2026-06-23 |
| `/board/v1` | 1기 아카이브 — 읽기 전용, ~ 2026-05-04 |

회차는 `src/config/boardVersion.ts`의 `BOARD_SEASONS` 한 곳에서 관리합니다. DB 마이그레이션 없이 작성 시각으로 나눕니다.

새 타운홀 회차를 시작할 때:

1. 현재 회차 항목에 `endsAt`을 채웁니다.
2. 배열 맨 뒤에 새 회차(`id`, `label`, `period`, `startsAt`)를 추가합니다.
3. (선택) `townHallAt`에 타운홀 일시를 넣으면 헤더에 `타운홀 D-n`이 표시됩니다.

라우팅(`/board/:seasonId`), 아카이브 드롭다운, 필터는 설정을 그대로 따라갑니다. 존재하지 않는 회차 주소는 `/board`로 이동합니다.

## Local Setup

```bash
npm install
```

Supabase 없이도 실행할 수 있습니다. 환경변수가 없으면 앱은 자동으로 데모 모드로 실행됩니다.

### Demo Mode

환경변수 설정 없이 실행:

```bash
npm run dev
```

- 헤더에 `데모 모드` 표시가 보이면 정상입니다.
- 포스트잇 데이터는 메모리상 데모 데이터로 동작합니다(현재 회차 9개 + 지난 회차 예시 2개).
- 새로고침하면 데모 초기 상태로 돌아갑니다.
- Supabase 환경변수가 있는데 연결에 실패하면 데모 데이터로 바꾸지 않고 "다시 불러오기" 화면을 보여줍니다. 실데이터와 데모 데이터가 섞여 저장되는 일을 막기 위해서입니다.

### Supabase Mode

1. `.env.example`을 참고해 `.env` 파일을 만듭니다.

```bash
cp .env.example .env
```

2. `.env`에 값을 채웁니다.

```bash
VITE_SUPABASE_URL=https://your-project-ref.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

3. Supabase에 아래 SQL을 순서대로 반영합니다.

- `supabase/migrations/202603232130_create_board_notes.sql`
- `supabase/migrations/202603241030_create_board_note_comments.sql`
- `supabase/migrations/202603241130_create_board_note_likes.sql`
- `supabase/migrations/202603241230_add_author_to_board_notes.sql`
- `supabase/migrations/202603241530_add_board_note_ordering.sql`
- `supabase/migrations/202603242030_add_board_note_image.sql` (사진 첨부)
- `supabase/migrations/202610151200_relax_board_note_content_length.sql` (본문 1000자 허용 — 화면 제한과 DB 제약을 맞춤)
- `supabase/migrations/202610151300_change_master_password.sql` (관리자 마스터 비밀번호 변경 + 빈 비밀번호(NULL)로 수정·삭제가 통과하던 문제 차단)
- 채팅까지 같이 확인하려면 `supabase/migrations/202603232230_create_chat_messages.sql`

4. 개발 서버를 실행합니다.

```bash
npm run dev
```

## Local Test Guide

이 프로젝트는 별도 테스트 러너 대신 `lint`, `build`, 수동 검증 중심으로 확인합니다.

### Static Checks

```bash
npm run lint
npm run build
```

### Manual Test: 작성 · 상세 · 수정

1. `/board`에서 `N` 또는 `포스트잇 붙이기`로 작성창을 엽니다. 카테고리를 바꾸면 안내 문구가 바뀌는지 확인합니다.
2. 내용을 적다가 배경을 눌러 닫은 뒤 다시 열면 `작성하던 내용을 불러왔어요`가 보이는지 확인합니다.
3. 비밀번호를 비운 채 `⌘/Ctrl + Enter`로 붙이면 토스트가 뜨고 새 포스트잇이 빈자리에 붙으며 깜빡이는지 확인합니다.
4. 방금 붙인 포스트잇을 눌러 상세 화면 → `수정`을 누르면 비밀번호 입력란 없이 저장되는지 확인합니다.
5. 다른 기기(또는 시크릿 창)에서는 같은 글 수정 시 비밀번호를 묻는지 확인합니다.
6. 상세 화면 댓글 입력에서 한글 입력 후 Enter로 등록되는지, Shift+Enter는 줄바꿈인지 확인합니다.

### Manual Test: 보기 · 정렬 · 순서

1. 툴바에서 `보드`/`목록`을 전환합니다. 목록에서만 정렬 선택이 보이는지 확인합니다.
2. 목록에서 `공감순`, `최신순`, `댓글순`으로 순서가 바뀌고, 상단 고정 글은 항상 위에 있는지 확인합니다.
3. 포스트잇 `⋯`(데스크톱은 우클릭)에서 `상단 고정`, `맨 위로` 등을 실행합니다. 맨 위 글은 위로 이동이, 맨 아래 글은 아래로 이동이 비활성인지 확인합니다.
4. 보드 보기에서 포스트잇을 캔버스 끝으로 끌어 놓아도 다른 포스트잇 위치가 바뀌지 않는지 확인합니다.

### Manual Test: 타운홀 모드

1. 헤더 `타운홀 모드` 또는 `T`로 엽니다. 시작 슬라이드에 총 개수·카테고리별 개수·자주 나온 말이 보이는지 확인합니다.
2. `→`로 넘기면 공감 많은 순서대로 나오는지, `R`을 누르면 카드가 굴러가다 하나가 뽑히는지 확인합니다.
3. `D`로 `이야기 나눔` 도장을 찍고, 랜덤 뽑기에서 이미 나눈 글이 빠지는지 확인합니다.
4. 마지막 슬라이드에서 나눈 개수가 보이고 `진행 기록 지우기`가 동작하는지 확인합니다.

### Manual Test: 회차 아카이브

1. 헤더 `지난 대나무숲` 드롭다운에서 지난 회차로 이동합니다.
2. `아카이브` 배지와 읽기 전용 안내가 보이고, 작성·순서 메뉴·드래그·공감·댓글 입력이 없는지 확인합니다.
3. 포스트잇을 누르면 읽기 전용 상세(댓글 포함)가 열리는지 확인합니다.
4. `/board/v9`처럼 없는 회차 주소는 `/board`로 이동하는지 확인합니다.

### Manual Test: Supabase 공유 반영

Supabase 환경에서 두 개의 브라우저 창을 열고 같은 `/board`를 띄운 뒤 확인합니다.

1. 창 A에서 포스트잇을 `상단 고정`하거나 순서를 변경합니다. 지난 회차 글이 있어도 실패하지 않아야 합니다.
2. 창 B에서 실시간 반영(댓글·공감), 30초 주기 동기화, 또는 탭으로 돌아올 때 순서가 반영되는지 확인합니다.
3. 창 A에서 새 포스트잇을 추가하면 해당 카테고리의 마지막 순서로 들어가는지 확인합니다.
4. 포스트잇 카테고리를 변경하면 새 카테고리 내 마지막 순서로 이동하는지 확인합니다.

## Agentation

개발 환경에서는 Agentation 툴바가 자동으로 붙습니다. 프로덕션 빌드에는 렌더되지 않습니다.

### Local Agentation Setup

1. 앱 실행

```bash
npm run dev
```

2. Agentation MCP 서버 실행

```bash
npm run agentation:mcp
```

3. 설정 진단

```bash
npm run agentation:doctor
codex mcp list
```

- 기본 엔드포인트는 `http://localhost:4747` 입니다.
- 다른 포트를 쓰려면 앱 실행 전에 `VITE_AGENTATION_ENDPOINT` 환경변수를 지정합니다.
- Codex 로컬 MCP는 `agentation-mcp server` 기준으로 연결하면 됩니다.

## Notes

- 정렬/고정 상태는 Supabase를 사용할 때 공용 상태로 저장됩니다.
- 보드/목록 보기, 타운홀 진행 기록(이야기 나눔), 마지막 방문 시각, 이 기기에서 쓴 글의 비밀값은 브라우저 저장소에만 남는 개인 상태입니다.
- 인증/관리자 권한은 아직 없어서, 현재는 누구나 공용 정렬을 바꿀 수 있습니다.
- 회차 분리는 `src/config/boardVersion.ts`의 `BOARD_SEASONS`로 관리됩니다. DB 변경 없이 프론트엔드에서 날짜 기준으로 필터링합니다.
